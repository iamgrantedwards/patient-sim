# Architecture

The Python dispatcher validates the single permitted assessment destination and starts a dedicated local LiveKit Agents worker. After registration is acknowledged, it dispatches one job into a uniquely named room. The worker joins, prepares recording and its STT → text LLM → TTS session, then places the outbound call through a Twilio Elastic SIP trunk using one fixed caller number. The initial providers are Deepgram Flux, GPT-4.1-mini, and Cartesia Sonic 3.6 through LiveKit Inference: one provider-access configuration keeps setup small while retaining separate pipeline components. Flux is our initial turn-detection candidate; VAD handles interruptions. The patient waits for the office greeting, uses synthetic facts, and speaks toward a scenario objective without receiving evaluator traps. Preemptive generation is initially off to avoid replies to incomplete turns; noise cancellation and automatic gain control are off to preserve the audio we evaluate. These are starting tradeoffs, not measured claims about voice quality or latency. The optional configuration comparison is deferred; current choices are engineering rationale, not comparative performance results.

The worker journals events as they arrive and turns committed message IDs into transcripts, keeping partial speech without duplicating turns. On session closure it preserves the SDK's stereo OGG before temporary cleanup and checks the container and complete decoding; only listening can establish a usable conversation. Provenance records code revision, scenario, prompt hash, models, and settings. Transcript claims remain separate from independently verified outcomes, and audio-derived timing stays unset until measured. The patient handles the farewell, with no second generated goodbye from the end-call tool. Ringing, duration, and turn limits bound failures, while cleanup still runs when evidence writing fails. The current local worker/dispatcher share a checkout; cloud deployment and a separate recording service are unnecessary for this assessment. A separate FastAPI process serves a loopback-only review interface with bundled HTML/CSS/JavaScript, native audio playback, an allowlisted evidence API, and visible governance limits. Its default is read-only without caller imports or credentials. An independent `--enable-reviews` flag permits token- and Origin-protected local review saves, using atomic writes, revision conflicts and a per-call file lock. Reviews retain revision history and evidence fingerprints in a separate `review.json`; stale reviews and legacy listening flags never qualify for usable counts; an explicit flag enables confirmed call controls backed by the same CLI controller. A shared OS lock, one-use confirmations, and durable recovery prevent accidental concurrent calls or redials; original files and unverified states remain intact. Offline tests verify safeguards and failure handling; subsequent SIP calls preserved decoded audio and ended through the end-call tool, while human listening acceptance remains pending. Abrupt process termination can still lose an unfinished recording, and IVR behavior remains a first-call observation.
